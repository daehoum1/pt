# 오아시스 대상자 자동 판별 프로그램 구현 요청

Python으로 사내 임직원의 근태 데이터를 분석하여 특별휴가인 **"오아시스" 대상자 여부를 자동 판별하는 로컬 웹 프로그램**을 만들어 줘.

현재 프로젝트 폴더에 샘플 파일로 다음 두 파일을 제공할 예정이다.

* `caps.xlsx`: 근태 엑셀 샘플
* `jandi.pdf`: 직출/직퇴 보고 PDF 샘플

먼저 두 샘플 파일의 실제 구조를 직접 확인한 다음 구현을 시작해 줘. 샘플 파일명이나 열 번호를 코드에 하드코딩하지 말고, 실제 운영 파일에서도 사용할 수 있게 일반화해 줘.

최종 사용자는 웹 화면에서 Excel 파일과 PDF 파일을 각각 업로드하고, 처리 버튼을 누른 뒤 결과 Excel 파일을 다운로드할 수 있어야 한다.

---

# 1. 기술 스택

다음 기술을 기본으로 사용해 줘.

* Python 3
* Streamlit: 파일 업로드 및 다운로드 UI
* openpyxl: 기존 Excel 파일 읽기/수정/저장
* PyMuPDF(`fitz`): PDF 텍스트 추출
* pytest: 핵심 로직 테스트

외부 LLM API, OpenAI API, Claude API 등은 사용하지 않는다.

PDF는 기본적으로 텍스트 PDF라고 가정한다.

프로젝트 구조는 가능하면 다음처럼 분리해 줘.

* `app.py`
* `oasis_processor.py`
* `requirements.txt`
* `README.md`
* `tests/test_processor.py`

핵심 처리 로직과 Streamlit UI 로직을 분리하여 테스트 가능한 구조로 만들어 줘.

# 2. Excel 입력 구조

샘플 Excel에는 아래와 같은 열이 존재한다.

* `번호`
* `사용자ID`
* `부서`
* `직급`
* `사원번호`
* `이름`
* `근무일자`
* `근무일명칭`
* `출근`
* `퇴근`
* `기본`
* `연장`
* `총합`
* `인정`
* `수정`

다만 실제 파일에서 열의 순서가 달라질 가능성을 고려하여 열 번호를 직접 사용하지 말고 반드시 **1행의 헤더 이름으로 필요한 열을 탐색**해 줘.

프로그램이 반드시 사용하는 필수 열은 다음 5개다.

* `이름`
* `근무일자`
* `출근`
* `퇴근`
* `기본`

필수 열 중 하나라도 없다면 처리하지 말고 사용자에게 어떤 열이 없는지 명확한 오류 메시지를 보여 줘.

사람별 데이터 사이 등에 완전히 빈 행이 존재할 수 있으므로 빈 행은 안전하게 무시해야 한다.

Excel의 시간은 상황에 따라 다음 형태일 수 있으므로 모두 처리할 수 있게 만들어 줘.

* Excel time 값
* `datetime.time`
* Excel serial number
* `"8:58"`
* `"08:58"`
* `"9:00"`

날짜 역시 Excel 날짜 객체 또는 문자열일 수 있으므로 정규화해서 `date` 기준으로 비교해 줘.

# 3. PDF의 직출/직퇴 데이터

PDF에는 직원별로 아래와 같은 형태의 보고가 존재한다.

예:

김맹구

[직퇴 보고]

• 일시: 2026.8.3.(월)

• 출발시간: 21시 (이동시간 1시간 10분)

• 사유: 123사비창작센터 미팅, 시설 관리 후 123사비창작센터에서 직퇴합니다.

[직출 보고]

• 일시: 2026.8.5.(수)

• 출발시간: 8시 45분 (이동시간 10분)

• 사유: 여행콘텐츠최강자전 택배발송을 위해 장재우체국으로 직출합니다.

이 데이터를 파싱하여 다음 구조의 데이터를 만들어 줘.

`(직원 이름, 날짜, 보고 유형) -> 시간`

보고 유형은 다음 두 가지다.

* `직출`
* `직퇴`

예:

* `(김맹구, 2026-08-03, 직퇴) -> 21:00`
* `(김맹구, 2026-08-05, 직출) -> 08:45`

---

# 4. PDF 파싱 시 매우 중요한 규칙

PDF의 형식 차이와 텍스트 추출 과정에서 발생할 수 있는 공백 차이를 견딜 수 있도록 정규식과 텍스트 정규화를 사용해 줘.

## 날짜

다음과 같은 표기를 모두 인식해야 한다.

* `2026.8.3.(월)`
* `2026.08.03.(월)`
* `2026. 8. 3.`
* 텍스트 추출 과정에서 중간에 불필요한 공백이 생긴 경우

항상 정규화한 최종 날짜는 `2026-08-03` 같은 `date` 값으로 사용한다.

### 매우 중요

PDF에 페이지 또는 섹션 제목으로 다음과 같은 날짜가 별도로 나타날 수 있다.

`2026년 8월 3일 월요일`

그러나 그 아래 개별 보고의 `일시:`가 다른 날짜일 수도 있다.

따라서 **페이지 제목이나 섹션 제목의 날짜를 사용해서는 안 된다.**

각 `[직출 보고]` 또는 `[직퇴 보고]` 안에 있는 **`일시:` 값을 유일한 기준 날짜로 사용한다.**

---

# 5. PDF 시간 파싱

다음 형태를 모두 처리해 줘.

* `21시`
* `21시 30분`
* `8시 45분`
* `08시 00분`
* PDF 추출 결과가 `21 30`, `8 45`처럼 `시`, `분` 문자가 일부 누락되는 경우

`출발시간:` 이후부터 여는 괄호 `(` 전까지의 값만 출발시간으로 해석하는 방식을 우선 사용해 줘.

예:

`출발시간: 21시 (이동시간 1시간 10분)`

여기서 출퇴근 시간은 **21:00**이다.

`1시간 10분`은 이동시간이므로 절대로 퇴근시간으로 해석하면 안 된다.

마찬가지로

`출발시간: 8시 45분 (이동시간 10분)`

의 출근시간은 **08:45**이다.

이동시간은 현재 오아시스 판정에 사용하지 않는다.

---

# 6. PDF에서 직원 이름 찾기

Excel의 `이름` 열에서 먼저 전체 직원 이름 목록을 수집해 줘.

PDF를 파싱할 때 `[직출 보고]`, `[직퇴 보고]` 앞에 있는 이름을 Excel 직원 목록과 비교하여 매칭하는 방식을 사용하면 된다.

이름 비교 시:

* 앞뒤 공백 제거
* 연속 공백 정규화

를 적용한다.

가능하면 Excel에 존재하지 않는 이름은 무시하되 로그에는 남겨 줘.

---

# 7. 중복 PDF 보고 처리

동일한

`이름 + 날짜 + 직출/직퇴`

조합이 PDF에 두 번 이상 존재할 수도 있다.

이 경우 PDF에서 **뒤에 등장한 보고를 최종값으로 사용**해 줘.

이는 수정된 보고가 뒤쪽에 있을 가능성을 고려한 것이다.

중복이 있었다는 사실은 로그에 남겨 줘.

---

# 8. Excel 출근/퇴근 누락값 보완

원본 Excel 파일을 직접 기반으로 수정한다.

절대로 새로운 형식의 Excel을 처음부터 만들지 않는다.

기존 데이터, 시트, 서식, 열 너비, 행 높이 등을 최대한 유지한다.

각 행에 대해:

## 출근이 이미 존재하는 경우

아무것도 변경하지 않는다.

PDF 데이터가 있더라도 기존 Excel 값을 덮어쓰지 않는다.

## 출근이 비어 있는 경우

동일한

`이름 + 근무일자 + 직출`

보고를 PDF에서 찾는다.

찾으면 PDF의 `출발시간`을 Excel의 `출근` 셀에 입력한다.

없으면 그대로 빈 셀로 둔다.

직퇴 보고를 출근에 사용하는 일은 절대 없어야 한다.

## 퇴근이 이미 존재하는 경우

아무것도 변경하지 않는다.

## 퇴근이 비어 있는 경우

동일한

`이름 + 근무일자 + 직퇴`

보고를 PDF에서 찾는다.

찾으면 PDF의 `출발시간`을 Excel의 `퇴근` 셀에 입력한다.

없으면 그대로 빈 셀로 둔다.

직출 보고를 퇴근에 사용하는 일은 절대 없어야 한다.

PDF에 보고가 존재하지만 Excel에는 해당 직원/날짜 행 자체가 없는 경우에는 새 행을 생성하지 않는다.

---

# 9. 기본(총 근무시간) 계산

사용자가 이 업무에서 `기본` 열을 총 근무시간으로 사용한다.

중요한 원칙:

**기존 `기본` 값이 있으면 절대로 변경하거나 다시 계산하지 않는다.**

`기본` 셀이 비어 있는 경우에만 계산한다.

PDF 보완까지 끝난 후:

* 출근 존재
* 퇴근 존재
* 기본이 비어 있음

이라는 세 조건을 만족할 경우

`기본 = 퇴근시간 - 출근시간`

으로 계산한다.

예:

* 출근 `08:45`
* 퇴근 `18:00`
* 기본 `09:15`

별도의 점심시간이나 휴게시간을 임의로 빼지 않는다.

현재 요구사항에는 그런 규칙이 없기 때문이다.

퇴근시간이 출근시간보다 숫자상 빠른 경우에는 자정을 넘긴 근무로 간주하여 24시간을 더해 계산한다.

예:

* 출근 22:00
* 퇴근 07:00
* 근무시간 09:00

계산한 `기본` 값은 Excel에서 시간으로 정상 표시되도록 `[h]:mm` 형식을 적용해 줘.

단, 기존 셀의 스타일을 최대한 보존한다.

출근이나 퇴근 중 하나라도 끝까지 없는 경우에는 `기본`을 임의 계산하지 말고 빈칸으로 유지한다.

---

# 10. PDF에서 보완하는 범위

출근/퇴근/기본 누락값 보완은 평일뿐 아니라 **Excel의 모든 날짜 행에 대해 수행**한다.

즉 토요일이나 일요일에 직출/직퇴 기록이 있어도 해당 Excel 행의 빈 출퇴근 시간은 PDF를 이용해 보완할 수 있다.

다만 오아시스 판정에서는 주말을 제외한다.

---

# 11. 오아시스 판정 기준

오아시스 여부는 **직원 단위**로 판정한다.

판정 기준은 다음 세 가지이며 **세 조건을 모두 만족해야 한다.**

## 조건 1. 모든 평일의 기본 근무시간이 9시간 이상

토요일과 일요일은 제외한다.

평일의 `기본` 값이 모두 `09:00` 이상이어야 한다.

`09:00`은 통과다.

예:

* 09:00 -> 통과
* 09:01 -> 통과
* 08:59 -> 실패
* 빈칸 -> 실패
* 00:00 -> 실패

## 조건 2. 모든 평일 출근시간이 오전 9시 이전 또는 정확히 9시

모든 평일의 출근시간이

`출근 <= 09:00`

이어야 한다.

따라서:

* 08:59 -> 통과
* 09:00 -> 통과
* 09:01 -> 실패
* 빈칸 -> 실패

## 조건 3. 모든 평일에 출근 및 퇴근 기록 존재

PDF 보완 작업까지 끝난 최종 상태를 기준으로 한다.

모든 평일에:

* 출근 존재
* 퇴근 존재

해야 한다.

둘 중 하나라도 비어 있으면 오아시스 대상자가 아니다.

---

# 12. 어떤 날짜를 "모든 평일"로 볼 것인지

Excel 전체의 `근무일자` 중 최소 날짜와 최대 날짜를 구한다.

그 사이에 존재하는 모든 월요일~금요일을 해당 파일의 평가 대상 평일로 정의한다.

예를 들어 Excel의 날짜 범위가

`2026-08-01 ~ 2026-08-13`

이라면 평가 날짜는 토·일을 제외한 모든 날짜다.

각 직원에게 해당 평일의 Excel 행 자체가 없다면 해당 직원은 그 날짜의 근태 기록이 없는 것으로 보고 오아시스 대상에서 제외한다.

다만 토요일/일요일 행이 없거나 근태가 부족한 것은 오아시스 판정에 영향을 주지 않는다.

---

# 13. 휴가/휴일/수정 등의 기존 상태값

현재 오아시스 규칙은 **"주말 제외"만 명시되어 있다.**

따라서 `수정` 등의 다른 열에 다음과 같은 값이 있더라도:

* `휴가`
* `휴일`
* `직퇴보고`
* `직출,직퇴보고`
* 기타 값

이를 임의로 오아시스 평가에서 제외하는 규칙을 추가하지 않는다.

즉 월~금요일이면 현재 요구사항에서는 평가 대상이다.

`연장`, `총합`, `인정`, `수정` 등의 열도 오아시스 판정에 사용하지 않는다.

기존 `수정` 열에 `O` 같은 값이 있더라도 이것은 새로 만드는 `오아시스 여부`와 전혀 다른 값이므로 판정 근거로 사용하지 않는다.

---

# 14. "오아시스 여부" 열 추가

기존 Excel의 가장 오른쪽 열 다음에 새로운 열을 하나 추가한다.

열 이름:

`오아시스 여부`

오아시스 조건 세 가지를 모두 만족한 직원은 해당 직원의 **모든 데이터 행**에:

`O`

를 입력한다.

대상자가 아닌 직원은 빈칸으로 둔다.

예:

| 이름  | 근무일자       | ... | 오아시스 여부 |
| --- | ---------- | --- | ------- |
| 홍길동 | 2026-08-01 | ... | O       |
| 홍길동 | 2026-08-02 | ... | O       |
| 홍길동 | 2026-08-03 | ... | O       |

처럼 직원 단위 판정 결과를 해당 직원의 각 행에 반복 표시한다.

---

# 15. 오아시스 셀 서식

`O`가 입력된 `오아시스 여부` 셀은 명확하게 보이도록:

* 배경색: 빨간색
* 글자색: 흰색
* 글자: 굵게
* 가로 가운데 정렬
* 세로 가운데 정렬

로 표시해 줘.

예를 들어 openpyxl의 solid fill을 사용하면 된다.

빨간색은 `FF0000` 계열을 사용해도 된다.

새로운 `오아시스 여부` 헤더 셀은 기존 마지막 헤더 셀의 스타일을 복사하여 기존 파일 디자인과 자연스럽게 맞춰 줘.

새 열 너비도 읽기 좋은 정도로 설정한다.

---

# 16. 원본 Excel 보존

매우 중요하다.

원본 Excel은 최대한 그대로 유지해야 한다.

다음은 유지한다.

* 기존 시트
* 기존 데이터
* 기존 셀 스타일
* 열 너비
* 행 높이
* 날짜 및 시간 표시 형식
* 수식
* 병합 셀
* 기존의 다른 열

기존 값은 다음 경우 외에는 수정하지 않는다.

1. `출근`이 비어 있고 대응되는 PDF 직출 보고가 존재할 때
2. `퇴근`이 비어 있고 대응되는 PDF 직퇴 보고가 존재할 때
3. `기본`이 비어 있고 출근/퇴근이 모두 존재하여 계산 가능할 때
4. 새 `오아시스 여부` 열 추가

출력 파일을 만들 때 원본 입력 Excel 파일 자체는 변경하지 않는다.

# 17. Streamlit UI

사용자가 쉽게 사용할 수 있도록 매우 단순한 화면을 만들어 줘.

화면 제목:

`오아시스 대상자 자동 판별`

다음 UI를 제공한다.

### Excel 업로드

`.xlsx` 파일 하나를 업로드할 수 있게 한다.

### PDF 업로드

`.pdf` 파일 하나를 업로드할 수 있게 한다.

### 처리 버튼

버튼 이름 예:

`근태 확인 및 오아시스 판정`

두 파일이 모두 업로드되었을 때만 처리할 수 있게 한다.

### 처리 결과 표시

처리가 끝나면 화면에 최소한 다음을 보여 준다.

* 전체 직원 수
* 오아시스 대상자 수
* 오아시스 대상자 이름
* PDF에서 출근시간을 보완한 건수
* PDF에서 퇴근시간을 보완한 건수
* 끝까지 출퇴근 기록을 찾지 못한 건수

### 다운로드

처리된 Excel을 다음과 같이 다운로드할 수 있게 한다.

`<원본파일명>_oasis_result.xlsx`

예:

`caps_oasis_result.xlsx`

`st.download_button`을 사용하고 가능하면 BytesIO 기반으로 처리해서 불필요한 임시파일 의존성을 줄여 줘.

# 20. 샘플 PDF를 이용한 필수 검증

현재 제공하는 `jandi.pdf`에서 최소한 아래 데이터가 제대로 파싱되는지 자동 또는 수동 테스트해 줘.

### 김맹구

* 2026-08-03 직퇴 -> 21:00
* 2026-08-05 직출 -> 08:45
* 2026-08-07 직퇴 -> 20:00

### 김철수

* 2026-08-03 직퇴 -> 21:30

### 김영희

* 2026-08-05 직출 -> 08:00

### 홍길동

* 2026-08-05 직출 -> 07:00
* 2026-08-05 직퇴 -> 16:00
* 2026-08-07 직출 -> 08:00
* 2026-08-07 직퇴 -> 16:30
* 2026-08-11 직출 -> 08:30
* 2026-08-11 직퇴 -> 17:30
* 2026-08-12 직출 -> 07:30

### 중요한 날짜 매칭 테스트

PDF의 어떤 섹션 제목이 `2026년 8월 3일`이라고 되어 있어도, 그 안의 홍길동 보고에

`일시: 2026.08.02`

라고 되어 있다면 그 보고는 **2026-08-02 데이터**로 처리해야 한다.

절대로 해당 직출/직퇴 시간을 홍길동의 `2026-08-03` Excel 행에 넣으면 안 된다.

# 21. 테스트 코드

단순히 프로그램만 작성하지 말고 `pytest` 테스트도 작성해 줘.

최소한 다음 테스트를 만든다.

1. PDF 날짜 파싱
2. PDF 시간 파싱
3. `21시` -> `21:00`
4. `8시 45분` -> `08:45`
5. 이동시간을 출퇴근시간으로 잘못 읽지 않는지
6. 직출은 출근에만 연결되는지
7. 직퇴는 퇴근에만 연결되는지
8. 기존 출근/퇴근을 덮어쓰지 않는지
9. 기본 빈칸 계산
10. 기본 기존값 보존
11. `09:00` 출근 통과
12. `09:01` 출근 실패
13. 기본 `09:00` 통과
14. 기본 `08:59` 실패
15. 출근 또는 퇴근 빈칸이면 실패
16. 토요일/일요일이 오아시스 판정에서 제외되는지
17. 같은 직원의 여러 평일 중 하루라도 실패하면 전체 직원이 탈락하는지
18. 직원에게 평가 대상 평일의 행 자체가 없으면 탈락하는지
19. PDF 중복 보고에서 마지막 보고를 사용하는지
20. 샘플 PDF의 김맹구/홍길동 등 주요 데이터 파싱
