세금계산서의 날짜가 입력되었을 떄, 이전에 작성되어야 했던 세 종류 문서를 자동으로 PDF파일로 생성해 주는 프로그램을 만들고 싶어. 발주서, 지출결의서, 물품검수조서를 생성해야 하고 세금계산서를 PDF의 형식으로 입력했을 때, 각 문서가 자동으로 생성되게 해야 해. 이때 세금계산서의 날짜를 인식하여 발주서, 지출결의서, 물품검사조서의 날짜가 자동으로 생성되어야 해. 발주서의 경우에는 세금계산서의 날짜를 기준으로 일주일 전의 임의의 평일로 되어야 하고, 지출결의서는 계산서와 동일한 날짜로, 물품검사조서는 세금계산서의 날짜의 다음 주의 임의의 평일로 되어야 해. 세금계산서를 업로드했을 때 자동으로 나머지 세 종류의 문서가 생성되도록 프로그램을 만들 것이야. 그리고 세금 계산서에서 품명을 인식하여 품목으로 자동 분류해서 나머지 문서에 작성하도록 해야 해. 이 프로그램의 구현을 위하여 클로드 코드를 이용할 거야. 이때 클로드 코드에게 입력해야 할 프롬프트를 작성해 줘.
===================
세금계산서 PDF를 업로드하면 내용을 자동으로 인식하고, 이를 바탕으로 발주서, 지출결의서, 물품검수조서를 PDF로 생성하는 프로그램을 만들어 주세요.

## 1. 개발 목표

사용자가 전자세금계산서 또는 스캔된 세금계산서 PDF 파일을 업로드하면 다음 작업을 자동으로 수행하는 로컬 웹 프로그램을 개발해 주세요.

1. 세금계산서 PDF 내용 인식
2. 세금계산서 작성일자 인식
3. 공급자 및 공급받는자 정보 인식
4. 품명, 규격, 수량, 단가, 공급가액, 세액, 합계금액 인식
5. 인식된 품명을 기준으로 품목 자동 분류
6. 날짜 규칙에 따라 문서별 작성일자 자동 계산
7. 발주서 PDF 생성
8. 지출결의서 PDF 생성
9. 물품검수조서 PDF 생성
10. 생성된 세 개 문서를 개별 다운로드하거나 ZIP 파일로 일괄 다운로드

프로그램은 외부 서버에 파일을 전송하지 않고 사용자 컴퓨터에서 로컬로 동작하도록 만들어 주세요.

## 2. 기술 스택

다음 기술을 우선적으로 사용해 주세요.

* Python 3.11 이상
* Streamlit: 사용자 인터페이스
* PyMuPDF 또는 pdfplumber: 텍스트가 포함된 PDF 내용 추출
* pytesseract 및 pdf2image 또는 PyMuPDF 이미지 변환: 스캔 PDF OCR
* 한국어 OCR 지원
* Jinja2 또는 별도의 템플릿 모듈: 문서 템플릿 관리
* ReportLab: PDF 생성
* PyYAML: 품목 분류 규칙과 프로그램 설정 관리
* pytest: 핵심 날짜 및 분류 기능 테스트

텍스트 레이어가 존재하는 PDF는 OCR을 사용하지 말고 텍스트를 직접 추출해 주세요. 텍스트 추출 결과가 부족한 경우에만 OCR을 적용해 주세요.

Mac과 Windows에서 모두 실행할 수 있도록 구성하고, 필요한 설치 방법을 README.md에 작성해 주세요.

분류 규칙은 `config/item_categories.yaml` 파일에서 수정할 수 있도록 구현해 주세요.

초기 분류 예시는 다음과 같습니다.

* 컴퓨터, 노트북, 모니터, 서버, GPU, CPU, 메모리, SSD, HDD → 전산장비
* 마우스, 키보드, 케이블, 어댑터, 허브, 충전기 → 전산소모품
* 프린터, 복합기, 토너, 잉크 → 사무기기 및 소모품
* 책상, 의자, 캐비닛, 선반 → 비품
* 실험장비, 계측기, 센서, 카메라, 렌즈 → 연구·실험장비
* 소프트웨어, 라이선스, 구독권 → 소프트웨어
* 복사용지, 문구, 파일, 펜 → 사무용품
* 위 규칙에 해당하지 않는 품목 → 기타

다음 기능도 포함해 주세요.

* 대소문자 및 띄어쓰기 차이 무시
* 부분 문자열 및 복수 키워드 매칭
* 유사 문자열 매칭
* 여러 분류가 동시에 매칭되면 우선순위가 높은 분류 선택
* 자동 분류 결과를 사용자가 드롭다운에서 변경 가능
* 사용자가 수정한 품목명과 분류를 새로운 규칙으로 저장할 수 있는 기능
* 여러 품목이 있을 경우 품목별 분류 제공
* 문서 전체의 대표 품목 분류도 선택 가능

분류 규칙은 소스코드를 수정하지 않고 YAML 파일만 수정하여 확장할 수 있게 해 주세요.

## 4. 날짜 자동 생성 규칙

세금계산서에서 인식한 작성일자를 기준일로 사용해 주세요.

문서별 날짜는 다음 규칙으로 생성합니다.

### 4.1 발주서

세금계산서 작성일자가 포함된 주의 바로 이전 주에서 월요일부터 금요일 사이의 날짜 하나를 선택합니다.

예를 들어 세금계산서 작성일자가 2026년 8월 6일 목요일이라면, 발주서 날짜는 2026년 7월 27일부터 7월 31일 사이의 평일 중 하나가 되어야 합니다.

### 4.2 지출결의서

지출결의서 날짜는 세금계산서 작성일자와 동일하게 설정합니다.

### 4.3 물품검수조서

세금계산서 작성일자가 포함된 주의 바로 다음 주에서 월요일부터 금요일 사이의 날짜 하나를 선택합니다.

예를 들어 세금계산서 작성일자가 2026년 8월 6일 목요일이라면, 물품검수조서 날짜는 2026년 8월 10일부터 8월 14일 사이의 평일 중 하나가 되어야 합니다.

### 4.4 날짜 선택 시 주의사항

완전히 무작위로 선택하면 동일한 세금계산서를 다시 처리할 때 날짜가 달라질 수 있으므로, 같은 세금계산서를 입력하면 항상 같은 날짜가 선택되는 결정적 방식으로 구현해 주세요.

다음 정보를 조합한 해시값을 랜덤 시드로 사용해 주세요.

* 세금계산서 작성일자
* 공급자 상호
* 합계금액
* 사업자등록번호

동일한 세금계산서에서는 항상 동일한 날짜가 생성되어야 합니다.

또한 다음 기능을 제공해 주세요.

* 자동 생성된 날짜를 사용자가 수정 가능
* 발주서 날짜가 세금계산서 날짜보다 늦어지지 않도록 검증
* 물품검수조서 날짜가 세금계산서 날짜보다 빨라지지 않도록 검증
* 토요일과 일요일은 선택하지 않음
* 한국 공휴일 제외 여부를 설정에서 선택할 수 있도록 구성
* 날짜 규칙을 `config/settings.yaml`에서 변경할 수 있도록 구성

기본 설정은 다음과 같이 해 주세요.

```yaml
date_rules:
  order_date: previous_calendar_week_random_weekday
  expense_date: same_as_invoice_date
  inspection_date: next_calendar_week_random_weekday
  exclude_weekends: true
  exclude_korean_holidays: false
  deterministic_random: true
```

* 세금계산서 작성일자가 존재하는지
* 공급자 정보가 존재하는지

* 수량과 단가가 숫자인지

## 10. OCR 및 세금계산서 파싱

세금계산서 PDF 형식이 공급업체마다 다를 수 있으므로 특정 좌표에만 의존하지 말아 주세요.

다음 순서로 처리해 주세요.

1. PDF 텍스트 레이어 확인
2. 텍스트가 충분하면 직접 추출
3. 텍스트가 없거나 부족하면 페이지를 이미지로 변환
4. 문서 방향 자동 보정
5. 한국어와 영어 OCR 실행
6. 주요 필드명을 기준으로 값 추출
7. 정규표현식과 주변 텍스트 분석을 함께 사용
8. 인식 결과를 구조화된 데이터로 변환

세금계산서 날짜는 다음 표현을 모두 처리해 주세요.

* 2026-08-06
* 2026.08.06
* 2026/08/06
* 2026년 8월 6일
* 20260806
* 작성일자: 2026-08-06

사업자등록번호는 `000-00-00000` 형식을 인식하고, 금액에서는 쉼표와 원 기호를 제거한 뒤 숫자로 변환해 주세요.

날짜가 여러 개 인식되면 다음 우선순위를 사용해 주세요.

1. 작성일자
2. 발행일자
3. 공급일자
4. 승인일자
5. 사용자가 직접 선택

세금계산서에서 날짜를 확정할 수 없는 경우 임의로 선택하지 말고, 인식된 날짜 후보를 사용자에게 보여 주어 선택하도록 해 주세요.

## 11. 테스트 요구사항

최소한 다음 자동 테스트를 작성해 주세요.

1. 세금계산서 날짜가 목요일일 때 이전 주 월요일부터 금요일 사이에서 발주서 날짜가 생성되는지
2. 다음 주 월요일부터 금요일 사이에서 검수조서 날짜가 생성되는지
3. 지출결의서 날짜가 세금계산서 날짜와 동일한지
4. 토요일과 일요일이 선택되지 않는지
5. 동일한 세금계산서를 여러 번 처리해도 같은 날짜가 생성되는지
6. 공급자나 금액이 달라지면 다른 날짜가 선택될 수 있는지
7. 여러 날짜 형식이 정상적으로 파싱되는지
8. 사업자등록번호가 정상적으로 추출되는지
9. 품명에 `노트북`이 포함되면 `전산장비`로 분류되는지
10. 품명에 `HDMI 케이블`이 포함되면 `전산소모품`으로 분류되는지
11. 알 수 없는 품목이 `기타`로 분류되는지
12. 공급가액과 세액, 합계금액이 일치하지 않을 때 경고가 발생하는지
13. 한글이 포함된 PDF가 깨지지 않고 생성되는지

예를 들어 세금계산서 날짜가 2026년 8월 6일인 테스트에서는 다음 조건을 검증해 주세요.

* 발주서 날짜: 2026년 7월 27일∼7월 31일
* 지출결의서 날짜: 2026년 8월 6일
* 물품검수조서 날짜: 2026년 8월 10일∼8월 14일

## 12. 개인정보와 보안

세금계산서에는 사업자등록번호, 주소 등 민감한 정보가 포함될 수 있으므로 다음 원칙을 적용해 주세요.

* 기본적으로 외부 API를 사용하지 않음
* 모든 분석과 PDF 생성은 로컬에서 처리
* 업로드 파일을 외부 서버로 전송하지 않음
* 로그에 사업자등록번호, 주소, 금액 전체를 출력하지 않음
* 오류 로그에서는 민감한 값을 마스킹
* 임시 업로드 파일은 작업 완료 후 삭제
* 생성 문서는 사용자가 다운로드한 후 세션에서 제거 가능

## 14. 실행 방법

최종적으로 다음 명령으로 실행할 수 있어야 합니다.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```
